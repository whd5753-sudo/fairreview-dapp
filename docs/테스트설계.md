# 컨트랙트 테스트 설계 — Hardhat (8단계 A~E, 10단계 F 추가)

파일: `contracts/test/FairReview.test.js` (mocha + chai + hardhat-chai-matchers)
4단계의 기대값 표처럼, **이 표가 정답지**다. 테스트가 실패하면 표가 아니라 코드를 고친다.
각 테스트는 `loadFixture` 로 새 컨트랙트에서 시작한다 (테스트끼리 영향 없음).

계정: `admin`(배포자) · `owner`(가게 1 사장님) · `customer`(손님) · `stranger`(아무 관계 없는 사람)
기본 준비(fixture): 배포 → admin 이 `registerStore(owner, "온정 김치찌개")`

## A. 가게 등록

| # | 상황 | 기대 |
|---|---|---|
| A1 | admin 이 등록 | `storeCount` 1, `stores(1)` = (owner, 이름), 이벤트 `StoreRegistered(1, owner, 이름)` |

## F. AI 오라클 서명 (10단계)

10단계부터 리뷰는 `submitReview(결제, 별점, 내용, 점수, 오라클 서명)` 이다. C 의 리뷰 테스트도 모두 오라클 서명(점수 0)을 붙여 제출한다.
서명은 오라클 서버와 **같은 코드**(`oracle/sign.mjs`)로 만든다. 준비: B1 의 결제 1번.

| # | 상황 | 기대 |
|---|---|---|
| F1 | 점수 550 (기대값 표 4번 문장) | 보류: `ReviewHeld(1, 1, customer, 4, 내용, 550)`, `reviewStatus(1)` = 2, 포인트 그대로, `reviewed` true |
| F2 | 점수 399 · 400 · 699 · 700 | 게시 · 보류 · 보류 · `SuspectedFakeReview(700)` (거부된 결제는 `reviewed` false) |
| F3 | 오라클이 아닌 지갑이 서명 | `InvalidOracleSignature` |
| F4 | 서명 뒤 내용 · 점수 · 별점을 바꿈 | 셋 다 `InvalidOracleSignature` |
| F5 | 다른 결제 · 다른 사람 · 다른 컨트랙트 · 다른 체인용 서명 | 넷 다 `InvalidOracleSignature` |
| F6 | 망가진 서명 (`0x1234`, 빈 서명) | `InvalidOracleSignature` |
| F7 | 점수 1001 | `InvalidScore(1001)` |
| F8 | 관리자가 보류 승인 | 상태 1(게시), 포인트 +10, `HeldReviewResolved(1, 1, true)` |
| F9 | 관리자가 보류 거절 → 다시 검토 | 상태 3(거절), 포인트 그대로 → `NotHeld(1)` |
| F10 | 보류가 아닌데 검토 / 사장님 · 손님이 검토 | `NotHeld(1)` / `NotAdmin` |
| F11 | 오라클 주소 0 으로 배포 / 배포 뒤 | `ZeroAddress` / `admin()` · `oracle()` 이 배포 값 |
| F12 | 비상 중지 중 보류 검토 | `ContractPaused` |
