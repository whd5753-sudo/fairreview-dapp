## 2. 읽기와 쓰기

| | 방법 | 지갑 필요 | 파일 |
|---|---|---|---|
| 읽기 (포인트 · 결제 기록 · 리뷰 목록) | 공개 노드 `ethereum-sepolia-rpc.publicnode.com` | 아니오 | `contracts/client.js` |

리뷰 목록은 `ReviewSubmitted` 이벤트를 가게 번호로 걸러 읽는다. 공개 노드의 범위 제한 때문에 40,000블록씩 나눠 찾는다.

## 3. 리뷰 제출 흐름 (`/stores/:id/review`)

1. AI 검사 (4단계 엔진) → **게시**일 때만 제출 칸이 열린다. 보류 = 10단계(오라클 · 사람 검토), 거부 = 제출 불가
2. 지갑 연결 · Sepolia 확인 (아니면 `Sepolia 로 전환` 버튼 = `wallet_switchEthereumChain`)
3. 결제 번호 입력 → **서명 전에 미리 확인** (수수료 낭비 방지, 최종 판단은 컨트랙트)
   - 없는 결제 · 다른 가게 결제 · 남의 결제 · 이미 쓴 결제 → 바로 안내
4. MetaMask 서명 → 블록에 담길 때까지 기다림 → 제출 완료 · Etherscan 링크 · 포인트 다시 읽기 (+10)

## 4. 오류 → 한국어 (`contracts/errors.js`)

| 오류 | 문장 |
|---|---|
| MetaMask 취소 | MetaMask 에서 요청을 취소했습니다 |
| 다른 가게 결제 (화면 검사) | 이 가게의 결제가 아닙니다. 결제 번호를 확인해 주세요 |
| `PaymentNotFound` | 없는 결제 번호입니다 |
| `NotPaymentCustomer` | 이 결제를 한 손님의 지갑이 아닙니다 |
| `AlreadyReviewed` | 이미 리뷰를 쓴 결제입니다 |
| `ReviewExpired` | 결제 후 30일이 지나 리뷰를 쓸 수 없습니다 |
| `InvalidRating` · `EmptyContent` · `ContentTooLong` · `ContractPaused` | 각각의 안내 |
| 수수료 부족 | 수수료로 낼 SepoliaETH 가 부족합니다 |
| 그 밖 | 블록체인 요청이 실패했습니다. 잠시 후 다시 시도해 주세요 (원래 메시지는 보여 주지 않음) |

## 6. 사람이 직접 확인 (Sepolia 실제 트랜잭션)

1. `npm run dev` → Edge(MetaMask 있는 브라우저)에서 `/fairreview-dapp/stores/1/review`
2. 지갑 연결 (Account 1) → 머리글에 `포인트 90P`
3. 예시: 게시 → 검사하기 → 결제 번호 `1` → 블록체인에 제출 → MetaMask 컨펌
4. 제출 완료 · Etherscan 링크 · 포인트 `100P`
5. `/stores/1` → "블록체인에 기록된 리뷰"에 방금 리뷰
6. 같은 결제 번호로 다시 제출 → "이미 리뷰를 쓴 결제입니다" (MetaMask 창이 뜨지 않아야 함)

## 7. 알려진 한계

- 화면의 가게 정보(메뉴 · 예시 리뷰)는 아직 예시 데이터. 2번 가게 이름이 화면은 "모퉁이 커피", 체인은 "모통이 커피" (등록할 때 오타 — 컨트랙트에 이름 변경 함수가 없어 그대로 둠)
- 공개 노드가 느리거나 막히면 리뷰 목록 · 포인트를 못 읽는다 (오류 문구 + 다시 시도)
- 빌드 파일이 500kB 를 넘는다는 경고 (ethers 포함). 동작에는 문제 없음
