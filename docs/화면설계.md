# 5단계 화면 설계 — 리뷰 미리 검사

손님이 리뷰를 쓰면, 블록체인에 올리기 **전에** AI 문장 판정 엔진(4단계 `engine.js`)으로
점수와 판정(게시 · 보류 · 거부)을 미리 보여 주는 한 페이지 화면이다.
여러 페이지 이동(라우팅)과 지갑 연결은 6단계 이후에 한다.

## 화면 구성 (위에서 아래로)

1. **머리글** — 제목 `FairReview`, 한 줄 설명 "결제한 손님만 쓰는 공정한 리뷰"
2. **리뷰 입력 카드**
   - 별점: 1~5 버튼 5개 (선택된 버튼 강조, 처음 값 5)
   - 리뷰 내용: 여러 줄 입력칸, 최대 300자, 아래에 `글자 수 N / 300` (N 은 `charCount` 로 계산)
   - `검사하기` 버튼 — 내용이 비어 있으면 누를 수 없음
   - 예시 버튼 3개: 기대값 표의 1번(게시) · 4번(보류) · 3번(거부) 행. 누르면 내용과 별점을 채움
3. **결과 카드** (검사하기를 누른 뒤에만 보임)
   - 점수 `N / 1000`
   - 판정 배지: 게시(초록) · 보류(주황) · 거부(빨강) — 색만이 아니라 글자로도 표시
   - 이유 목록: `reasons` 를 한 줄씩. 비어 있으면 "걸린 규칙 없음"
   - 안내 문구: "이 결과는 미리 보기입니다. 실제 게시 여부는 8단계에서 컨트랙트가 결정합니다."

## 규칙

- 점수 · 판정은 **`engine.js` 의 `analyzeText` · `decide` 만** 사용한다. 화면 코드에서 점수를 따로 계산하지 않는다.
- `engine.js` · `engine.test.js` · `docs/기대값표.md` 는 고치지 않는다.
- 상태(`useState`)는 `App` 에 둔다: 내용 · 별점 · 결과. 입력이 바뀌면 이전 결과는 지운다.
- 입력칸과 별점에는 `label` 을 연결하고, 버튼에는 `type="button"` 을 쓴다.
- 폭 360px 휴대폰에서도 가로 스크롤이 생기지 않게 한다.
- 사용자가 입력한 글은 화면에 글자로만 보여 준다 (`dangerouslySetInnerHTML` 금지).

## 파일

| 파일 | 하는 일 |
|---|---|
| `web/index.html` | 화면의 뼈대, `src/main.jsx` 를 불러옴 |
| `web/vite.config.js` | React 플러그인, `base: '/fairreview-dapp/'` (Pages 주소의 하위 폴더) |
| `web/src/main.jsx` | `App` 을 화면에 붙임 |
| `web/src/App.jsx` | 상태를 갖고 두 카드를 배치 |
| `web/src/components/ReviewForm.jsx` | 별점 · 내용 입력, 예시 버튼, 검사하기 버튼 |
| `web/src/components/ResultCard.jsx` | 점수 · 판정 배지 · 이유 목록 |
| `web/src/App.css` | 모양 |
