# 발표 준비 — 시연 순서 · 캡처 목록 · 예상 질문

발표 자료(슬라이드)는 Claude 가 만든 초안을 본인 말로 고친다. 이 문서는 발표 직전에 보는 체크리스트다.

## 1. 발표 전날 준비

- [ ] MetaMask: Account 1(관리자 · 손님) · Account 2(사장님) 둘 다 SepoliaETH 0.005 이상 (부족하면 Faucet — 하루 1번)
- [ ] 시연용 결제 만들기: Remix 에서 Account 2 로 `recordPayment(1, Account 1, 9000)` 2건 더 (게시 · 보류 시연용). 결제 번호 메모
- [ ] `oracle` 폴더에서 `npm start` 가 되는지 (`컨트랙트 0x8773…ED0D` 출력)
- [ ] Edge 에서 https://whd5753-sudo.github.io/fairreview-dapp/ 지갑 연결 · Sepolia · 포인트 표시 확인
- [ ] 아래 캡처를 슬라이드에 넣어 두기 (시연이 실패해도 캡처로 설명)

## 2. 라이브 시연 순서 (약 5분)

| # | 화면 | 말할 것 |
|---|---|---|
| 1 | 홈 → 가게 목록 → 온정 김치찌개 | "블록체인에 기록된 리뷰"는 지갑 없이 공개 노드에서 읽는다 |
| 2 | 리뷰 쓰기 → 예시: 거부 → 검사하기 | 990점 거부, 이유 3줄. 거부는 제출 칸 자체가 없다 |
| 3 | 예시: 게시 → 결제 번호 → 블록체인에 제출 | ① 결제 확인 ② **오라클 서명** ③ MetaMask ④ 기록 — 오라클 서버 터미널에 `[서명] … 게시` 가 찍힌다 |
| 4 | 같은 결제 번호로 다시 제출 | "이미 리뷰를 쓴 결제" — MetaMask 창이 안 뜬다 (수수료 0) |
| 5 | 예시: 보류 → 다른 결제 번호 → 제출 | 550점 보류로 기록, 포인트는 아직 |
| 6 | 바닥글 → 관리자: 보류 리뷰 검토 → 승인 | 관리자만 승인, 승인 때 +10P, 가게 화면에 "검토 후 게시" |
| 7 | Etherscan 에서 컨트랙트 → Events | 누구나 볼 수 있는 기록 (ReviewSubmitted · ReviewHeld · HeldReviewResolved) |
| 8 | (선택) VS Code 터미널 `npm run mutation` | 16/16 — 테스트가 검사를 지킨다 |

## 4. 예상 질문과 답 (본인 말로 다듬기 ✏️)

| 질문 | 답의 뼈대 |
|---|---|
| 왜 AI 를 컨트랙트 안에서 안 돌리나? | 블록체인은 모든 노드가 같은 계산을 반복 — AI 는 비싸고 결과가 결정적이지 않다. 그래서 체인 밖에서 계산하고 **서명만** 체인이 확인 (오라클 패턴) |
| 오라클 서버가 거짓 점수를 주면? | 오라클을 믿는 구조라 막을 수 없다 — 키 관리 · 여러 오라클 · 교체 함수가 실서비스 과제. 대신 **오라클 아닌 사람의 위조**와 **서명 뒤 바꿔치기**는 막는다 (F3~F5) |
| 사장님이 가짜 결제를 만들면? | 못 막는다 (T2). 셀프 결제만 막음. 진짜로 막으려면 카드사 · PG 가 결제에 서명해야 함 |
| 포인트를 왜 못 넘기게? | 넘길 수 있으면 리뷰를 포인트로 사고팔 수 있다. 보내기 함수가 없다는 걸 테스트 D4 가 확인 |
| 별점이 높으면 보상을 더 주면 안 되나? | 5점을 유도하게 된다 → 별점과 상관없이 10P (테스트 C10) |
| 리뷰를 지울 수 있나? | 없다. 공개 · 영구 → 개인정보 금지 안내. 실서비스라면 내용은 체인 밖, 해시만 체인 |
| 왜 Sepolia 만? | 수업 규칙 · 실제 자산 위험 없음. 메인넷 설정은 만들지 않았다 (CLAUDE.md 규칙 1) |
| AI 가 짠 코드를 어떻게 믿었나? | 정답지를 사람이 먼저 · AI 는 정답지를 못 고치게 · 훅과 CI · 뮤테이션으로 테스트 자체를 검증 · 보안 서브에이전트 |
| 가스비는? | Sepolia 실제 측정: 배포 909만 · 리뷰 약 5~7만. 로컬보다 크게 나옴 (코드 저장 비용) → 최적화로 18% 절약 |
