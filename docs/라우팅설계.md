# 6단계 라우팅 설계 — 여러 화면 · 지갑 Context · 404

5단계의 한 페이지 화면을 **여러 화면(주소)** 으로 나누고, 지갑 연결 상태를 **Context** 로 앱 전체에 나눠 준다.
가게 · 리뷰 데이터는 아직 블록체인이 없으므로 **고정된 예시 데이터**를 쓴다 (8단계에서 컨트랙트로 바꾼다).

## 1. 주소(라우트)

| 주소 | 화면 | 내용 |
|---|---|---|
| `/` | 홈 | 프로젝트 소개 3줄 + `가게 둘러보기` 링크 |
| `/stores` | 가게 목록 | 가게 카드 3개. 카드를 누르면 상세로 (Link) |
| `/stores/:id` | 가게 상세 | 가게 이름 · 메뉴 · 게시된 리뷰 목록 + `리뷰 쓰기` 링크. **없는 id 면** "없는 가게입니다" + 목록으로 가는 링크 (데이터 없음 ≠ 404) |
| `/stores/:id/review` | 리뷰 쓰기 | 5단계 화면(별점 · 내용 · 검사하기 · 결과). 맨 위에 가게 이름. 없는 id 면 상세와 같은 안내 |
| `*` | 404 | "페이지를 찾을 수 없습니다" + 홈으로 가는 링크 |

- 공통 부분(머리글 · 메뉴 · 바닥글)은 `Layout.jsx` 하나에 두고 가운데는 `<Outlet />`.
- 메뉴는 `NavLink` 로 `홈` · `가게 목록`. 지금 있는 화면의 메뉴는 강조.
- 앱 안에서 이동은 전부 `Link` / `NavLink`. `<a href="/...">` 를 쓰지 않는다.
- `:id` 는 **문자열**이다. 예시 데이터의 id 도 문자열(`"1"`, `"2"`, `"3"`)로 두고 `===` 로 비교한다.

## 2. 예시 데이터 `web/src/data/stores.js`

가게 3개. 가게마다 `id`, `name`, `category`, `menu`(이름 · 가격 2~3개), `reviews`(rating · content 2개).
리뷰 문장은 기대값 표의 **게시** 행처럼 구체적인 문장으로 쓴다.

## 3. 지갑 Context `web/src/state/WalletContext.jsx`

- 담는 값: `account`(연결된 주소 또는 null) · `chainId` · `isSepolia` · `connect()` · `disconnect()` · `error`.
  **자주 바뀌지 않는 값만** 담는다 (리뷰 입력 글자는 Context 에 넣지 않는다).
- `connect()` 는 `window.ethereum.request({ method: "eth_requestAccounts" })` 만 쓴다.
  MetaMask 가 없으면 `error` 에 "MetaMask 가 필요합니다".
- `accountsChanged` · `chainChanged` 이벤트를 듣고, `useEffect` 정리 함수에서 반드시 해제한다.
- Sepolia 의 chainId 는 `0xaa36a7`. 다른 체인이면 머리글에 "Sepolia 로 바꿔 주세요" 경고.
- `disconnect()` 는 화면 상태만 지운다 (MetaMask 연결 자체는 MetaMask 에서 끊는다).
- 개인키 · 니모닉 · 서명 요청은 이 단계에서 **하지 않는다**.
- 머리글 오른쪽: 연결 전 `지갑 연결` 버튼, 연결 후 `0x1234…abcd` 처럼 앞 6 · 뒤 4 글자.
- `useWallet()` 훅으로 꺼내 쓴다. Provider 밖에서 부르면 오류를 낸다.

## 4. GitHub Pages 새로고침 404 대책

- `main.jsx`: `<BrowserRouter basename={import.meta.env.BASE_URL.replace(/\/$/, "")}>` — `vite.config.js` 의 `base` 와 맞춘다.
- `web/scripts/copy-404.mjs`: 빌드 후 `dist/index.html` 을 `dist/404.html` 로 복사.
- `package.json` 의 build: `vite build && node scripts/copy-404.mjs`.

## 5. 5단계 문제 고치기 — 글자 수 기준 통일

입력 제한(300자)과 카운터를 **같은 기준(공백 포함, `content.length`)** 으로 맞춘다.
카운터 문구는 `글자 수 N / 300 (공백 포함)`. 엔진의 `charCount`(공백 제외)는 점수 계산에만 쓴다.

## 6. 테스트 (추가, 기존 engine 테스트는 그대로)

React Testing Library + `MemoryRouter` 로 화면 테스트 `web/src/test/routes.test.jsx`:

1. `/` → "가게 둘러보기" 링크가 보인다
2. `/stores` → 가게 3개 이름이 보인다
3. `/stores/1` → 1번 가게 이름이 보인다
4. `/stores/999` → "없는 가게입니다" (404 화면이 아님)
5. `/없는/주소` → "페이지를 찾을 수 없습니다" + 홈 링크
6. `/stores/1/review` → 거부 예시 넣고 검사하기 → "판정: 거부"
7. MetaMask 가 없을 때 `지갑 연결` → "MetaMask 가 필요합니다"
8. 글자 수: 공백 포함 "a b" → `글자 수 3 / 300`
