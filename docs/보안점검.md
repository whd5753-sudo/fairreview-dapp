## 3. 취약 → 안전 비교 (7주차 실습 2의 3·4번을 우리 코드로)

### 취약한 버전 — 영수증 한 장으로 리뷰 도배

```solidity
function submitReview(uint256 paymentId, uint8 rating, string calldata content) external whenNotPaused {
    Payment storage p = payments[paymentId];
    if (p.customer == address(0)) revert PaymentNotFound(paymentId);
    if (msg.sender != p.customer) revert NotPaymentCustomer(paymentId);
    // (빠짐) if (p.reviewed) revert AlreadyReviewed(paymentId);
    ...
    // (빠짐) p.reviewed = true;
    points[msg.sender] += REVIEW_POINTS;
    emit ReviewSubmitted(paymentId, p.storeId, msg.sender, rating, content);
}
```

결제 한 번으로 리뷰를 몇 번이고 쓸 수 있다. 쓸 때마다 10포인트가 쌓이고, 가게 평점도 한 사람 마음대로 움직인다.

### 안전한 버전 — 지금 코드 (145 · 151줄)

```solidity
    if (p.reviewed) revert AlreadyReviewed(paymentId);   // ③ 이미 쓴 결제인가
    ...
    p.reviewed = true;                                   // 포인트 · 이벤트보다 먼저 장부에 표시
```

| | 취약 | 안전 |
|---|---|---|
| 같은 결제로 두 번째 리뷰 | 통과, 포인트 110 | `AlreadyReviewed(1)` 로 거부, 포인트 100 그대로 |
| 테스트 C4 | 실패 (뮤테이션 M1 · M2) | 통과 |
| 화면 | — | 서명 전에 "이미 리뷰를 쓴 결제입니다" (수수료도 안 나감) |
| Sepolia 실제 기록 | — | 결제 1번 `reviewed = true` (리뷰 tx `0xbd660a6e…5794ba`) |

무엇이 달라졌나 ✏️: 리뷰 자격을 "이 결제의 손님인가"만 보지 않고 "이 결제를 이미 썼는가"까지 본다. 그리고 그 표시를 보상(포인트)보다 **먼저** 남긴다 — 나중에 외부 호출이 생겨도 같은 결제로 다시 들어올 수 없다(CEI).

## 7. AI 가 만든 코드 점검 (체크리스트 9번째 — 이 프로젝트에서 덧붙임) ✏️
