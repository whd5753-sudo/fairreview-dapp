# 8단계-1 컨트랙트 테스트 설계 — Hardhat

파일: `contracts/test/FairReview.test.js` (mocha + chai + hardhat-chai-matchers)
4단계의 기대값 표처럼, **이 표가 정답지**다. 테스트가 실패하면 표가 아니라 코드를 고친다.
각 테스트는 `loadFixture` 로 새 컨트랙트에서 시작한다 (테스트끼리 영향 없음).

계정: `admin`(배포자) · `owner`(가게 1 사장님) · `customer`(손님) · `stranger`(아무 관계 없는 사람)
기본 준비(fixture): 배포 → admin 이 `registerStore(owner, "온정 김치찌개")`

## A. 가게 등록

| # | 상황 | 기대 |
|---|---|---|
| A1 | admin 이 등록 | `storeCount` 1, `stores(1)` = (owner, 이름), 이벤트 `StoreRegistered(1, owner, 이름)` |
| A2 | stranger 가 등록 | `NotAdmin` |
| A3 | owner 주소가 0 | `ZeroAddress` |
| A4 | 이름이 빈 문자열 | `EmptyName` |

## B. 결제 기록

| # | 상황 | 기대 |
|---|---|---|
| B1 | owner 가 customer 에게 9000원 | `paymentCount` 1, `points(customer)` 90, 이벤트 `PaymentRecorded(1, 1, customer, 9000, 90)` |
| B2 | stranger 가 기록 | `NotStoreOwner(1)` |
| B3 | 없는 가게 2번 | `StoreNotFound(2)` |
| B4 | 손님 주소 0 | `ZeroAddress` |
| B5 | 금액 0 | `InvalidAmount` |
| B6 | 금액 10,000,001 | `InvalidAmount` (10,000,000 은 통과) |
| B7 | owner 가 자기 자신에게 | `SelfPayment` |
| B8 | 50원 결제 | 통과, 적립 0 (1% 미만은 버림 — 곱한 다음 나누므로 계산은 정확) |

## C. 리뷰 제출 (관문 순서대로)

준비: B1 의 결제 1번이 있는 상태

| # | 상황 | 기대 |
|---|---|---|
| C1 | customer 가 1번 결제로 별점 5 | 통과, `points(customer)` 100, `payments(1).reviewed` true, 이벤트 `ReviewSubmitted(1, 1, customer, 5, 내용)` |
| C2 | 없는 결제 9번 | `PaymentNotFound(9)` |
| C3 | stranger 가 1번 결제로 | `NotPaymentCustomer(1)` |
| C4 | 같은 결제로 두 번째 | `AlreadyReviewed(1)` |

| C6 | 결제 후 30일 + 1초 | `ReviewExpired(1)` |

## D. 비상 중지 · 포인트

| # | 상황 | 기대 |
|---|---|---|
| D1 | stranger 가 `pause` | `NotAdmin` |
| D2 | admin 이 `pause` 후 등록 · 결제 · 리뷰 | 셋 다 `ContractPaused`, 이벤트 `Paused(admin)` |
| D3 | `unpause` 후 다시 결제 | 통과, 이벤트 `Unpaused(admin)` |
| D4 | 포인트는 넘길 수 없다 | ABI 에 `transfer` · `approve` · `transferFrom` 함수가 없다 |

## E. 가스 (참고용 출력)

`registerStore` · `recordPayment` · `submitReview` 의 `gasUsed` 를 `console.log` 로 한 번 출력한다 (실패 조건 아님).
